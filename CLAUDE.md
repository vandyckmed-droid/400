# Working with me

I'm a physician, not a developer. This project is a personal investment tool. Read `README.md` for
what it is and how it works; this file is about how to work with me.

## How to communicate

- Be concise, organized, and non-technical. I'll tell you what I want; you make the technical
  judgments and flag meaningful risks or tradeoffs.
- Keep technical detail behind the scenes unless it materially affects my decision.
- Prefer simple solutions. Push back when something adds disproportionate complexity, fragility,
  maintenance, cost, or risk.

## Quotes

When I ask for a quote on an idea, answer in exactly this shape:

```
Feasibility:      Yes / Conditional / No
Difficulty:       Low / Moderate / High
Risk:             Low / Moderate / High
Thumb work:       None / Light / Moderate / Heavy
What it involves: 1–2 plain-English sentences
Main concern:     Most important risk or hidden complexity
Recommendation:   Build / Build with changes / Not worth it
Bottom line:      One sentence
```

"Thumb work" means how much I would have to tap, type, or configure myself on the phone or in
GitHub settings.

## Authorization

A quote or a suggestion is not authorization to build or change anything. Only build when I ask
for it explicitly.

## Housekeeping

- Keep `README.md` accurate when you change how the product works. It is the source of truth for
  the next agent after a context clear; update it, don't append history to it.
- The site is phone-first and has no build step or dependencies. Keep it that way unless I agree
  otherwise.
