# Working in this repository

I'm a physician, not a developer. This is my personal investment tool. `README.md` says what it is
and how it works; this file says how to work on it and with me.

## How to communicate

- Be concise, organized, and non-technical. I'll tell you what I want; you make the technical
  judgments and flag meaningful risks or tradeoffs.
- Keep technical detail behind the scenes unless it materially affects my decision.
- Prefer simple solutions. Push back when something adds disproportionate complexity, fragility,
  maintenance, cost, or risk.

## Quotes

When I ask for a quote on an idea, answer in exactly this shape:

```
Feasibility:      Yes / Conditional / No
Difficulty:       Low / Moderate / High
Risk:             Low / Moderate / High
Thumb work:       None / Light / Moderate / Heavy
What it involves: 1–2 plain-English sentences
Main concern:     Most important risk or hidden complexity
Recommendation:   Build / Build with changes / Not worth it
Bottom line:      One sentence
```

"Thumb work" means how much I would have to tap, type, or configure myself on the phone or in
GitHub settings.

## Authorization

A quote or a suggestion is not authorization to build or change anything. Only build when I ask
for it explicitly.

## How it is built, in brief

Plain HTML, CSS and JavaScript in the repo root, no build step, no packages. Two Python scripts in
`scripts/` (standard library only) fetch prices from FMP, compute the ranking and write static JSON
under `data/`. A GitHub Action runs them each weekday morning and commits the result. GitHub Pages
serves `main` as-is.

## Commands

```sh
FMP_API_KEY=... python3 scripts/build.py   # rebuild data/; needs the key, caches fetches 12 h
python3 -m http.server 8000                # serve locally; open http://localhost:8000
node --check app.js chart.js               # syntax check the browser code
python3 -m py_compile scripts/*.py         # syntax check the pipeline
```

There is no test suite. After a change, open the list, a detail page, its price chart and
Settings in a browser and check the console is clean.

## Gotchas

- `data/` is regenerated by the pipeline. Don't hand-edit it; change `build.py` and rebuild.
- The FMP key lives only in the `FMP_API_KEY` repository secret and the environment. Never put it
  in a file or in browser code.
- `build.py` deliberately exits non-zero when the data looks degraded. That is the safeguard, not
  a bug.
- The `.nojekyll` file looks empty and useless. It is required for Pages to serve the site.
- The old research section (backtests, indicator studies) is on the `archive/research` branch.
  Don't bring it back into the app; a finding that should become a feature goes through
  `build.py`.

## Housekeeping

- Keep `README.md` accurate when you change how the product works. It is the source of truth for
  the next agent after a context clear; update it, don't append history to it.
- The site is phone-first and has no build step or dependencies. Keep it that way unless I agree
  otherwise.
